# Colibri substep validation, 2026-09-17

Use the production solver at 120 Hz collision refresh, one solver iteration,
authored density scale 1.0, the current adjacent-tail collision filters,
and the normal free base. This study changes only substeps per refresh.
It is separate from the fixed-24-substep performance goal.

The existing gates are fresh penetration below 1 mm, model joint anchors
below 2 mm, model joint-axis vector mismatch below 0.03, assembly/velocity
bounds, and crank tracking within 5% after settling. Motor-off checks also
require support drift below 50 micrometers and rotation below 0.0005 rad
after two seconds. No thresholds are relaxed. Joint metrics below are the
independent geometry audit and need not identify the same worst joint as
the model-axis check.

All powered rows below use one world. Failed runs stop at the first gate
violation; their reported peaks are **not** full-minute error bounds.
Passing 24 is a short screen; existing four-world full-minute validation
covers the default setting separately.

The lowest passing count tested is 22. It completed 60 measured seconds
after one second warmup, at 13.3873 ms/frame without rendering. Most lower
counts fail on toroidal-gear/cylinder contact penetration, not on joint
separation. Four-world and motor-off confirmation both pass. The example default
remains 24.

Reproduce a full-minute count sweep:

```bash
uv run --no-sync -m local_studies.colibri.profile_substeps --substeps 22 21 20 --frames 3600 --output /tmp/colibri-substeps.json
```

Use `--worlds 4` for the default replicated scene and `--motor-off` for
unpowered drift checks. The diagnostic reports physics-only wall time
separately from audit work and includes warmup in error maxima.

Raw reports: `/tmp/colibri_substep_sweep.json`,
`/tmp/colibri_substep_refine.json`, `/tmp/colibri_substep_boundary.json`.

## Confirmation at 22 substeps

Both confirmation runs completed 3600 measured frames after 60 warmup:

| Configuration | Physics ms/frame | Depth (mm) | Anchor (mm) | Axis (degrees) |
| --- | ---: | ---: | ---: | ---: |
| Four worlds, motor on | 16.1624 | 0.523 | 0.883 | 0.517 |
| One world, motor off | 14.1205 | 0.269 | 0.302 | 0.269 |

All assembly and applicable drive/support tests passed. Motor-off support
stationarity passed the unchanged 50-micrometer / 0.0005-radian bounds;
this run records pass/fail, not a separate numerical drift maximum.
The four-world error peaks exactly match the single-world powered result.
Timings are standalone runs, not an interleaved speedup measurement.

Reports: `/tmp/colibri_substep22_multi.json` and
`/tmp/colibri_substep22_unpowered.json`. The reusable CLI also reproduces
the four-substep quality failure at frame 7 and passes a short 22-substep
smoke run: `/tmp/colibri_substep_cli_check.json`.

Use `uv run -m newton.examples phoenx_colibri --substeps 22` to try the
validated lower-count option. This means 22 substeps per 120-Hz collision
refresh, or 44 per displayed 60-Hz simulation frame. It is the lowest
**tested** passing count, not a proof for arbitrarily long runs or
interactive disturbances. Counts 4, 6, 8, 12, 16, 18, 19, 20 and 21 failed
the existing gates. Keep 24 as the default with more numerical margin.
